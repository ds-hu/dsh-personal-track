# 素材图片按 base64 存进域内的 `assets` 表，而不是域外的二进制文件

专注模式允许把长图（讲义、题目、书页截图）粘到某个**登记**条目上，于是插件需要存二进制。选择是：把图片字节作为 base64 放进域内的新表 `assets`（每张一个 per-record JSON 文档），还是把字节写到域外的某个目录、记录里只留路径，再用一条二进制路由读回来。我们选了前者。理由是**域是一整套已经成立的东西**：zod 在持久读边界逐条校验、per-record 布局让每张图各自成文档、storage hub 负责落盘与重启回读、备份/导入是一条已经验证过的往返路径。域外二进制要把这四件事都重做一遍——第二个存储位置（插件数据目录归属在 DSH 里还没有答案）、备份仍得把字节 base64 进 JSON（否则「导出后再导入得到原样」这条不变量就破了）、删除与孤儿回收多一套生命周期、还要一条绕开 JSON 管道的路由。base64 的代价（体积 +33%、JSON 文档里一坨长字符串）是**局部的、可度量的**，而域外存储的代价是**结构性的、分散在每个写路径上的**。真正被这条决定牺牲的是「域里只有小文档」的直觉，因此补了两个兜底：单张图 10 MB 上限（两半身共用 `MAX_IMAGE_BYTES` 一个常量），以及**素材清扫**入口回收被中断的写入留下的孤儿字节。

- **Status**: accepted
- **Considered Options**
  - 域外二进制文件 + 二进制路由 —— 否决：第二个存储位置、插件数据目录归属待调研、备份仍要 base64、删除与回收要另写一套。
  - 图片字节直接嵌进任务/媒体记录 —— 否决：每一次 `state()` 都会拖着所有图回来，读一页数据要付几 MB。
  - 把图存成 data URL 塞进素材字段 —— 否决：等于上一条，只是把超长字符串放进了文本字段。
- **Consequences**
  - 图片字节是**唯一**被持久化的东西：mime 与大小都从字节派生（`base64Bytes`），所以文件里不存在能与图片本身矛盾的字段。
  - 渲染不走 JSON：`GET /habit/api/asset?id=…` 是唯一返回二进制的路由，`<img src>` 直接指向它，浏览器按 URL 缓存（内容是 per-id 不可变的）。
  - `assets` 表没有 owner 字段：条目通过 `materialImage.assetId` 引用它，删除级联与孤儿清扫都读这份引用，不维护第二份可能漂移的关系。
  - 备份 v2 带 `assets` 数组并兼容 v1；导入时引用完整性是**整份拒绝**的规则之一（图片素材缺字节即整份不合法），与本插件既有的校验姿态一致。
  - 域的 `version` 从 1 升到 2，并列出 `compatibleVersions: [1]`：per-record 后端对不接受的版本是**直接丢弃**而不是迁移，漏掉这一行会让一年的习惯日在升级后首次重启时消失。
