# 每个写操作都回答它改动的**习惯日**切片，**登记**的写带一个"视点日"

本插件的写入曾按路由家族分三种答复：日级写答整份 `StateView`、**登记**写答 `{list, entry}`、**素材**与**专注**写只答 `{entry}`。客户端因此有两条采纳路径：`act` 直接采纳，`registryAct` 先把已经付过钱的列表丢掉、再补一次 `state(date)` 读——一次勾选两个往返，且写答案与补读谁后到并不确定。我们改为**一条规则**：任何写都答它改动的**习惯日** slice（`ok` + `day` + `stock` + `tasks` + `media`），外加这次写独有的事实——**登记**/素材/专注写附 `entry`，开一段**专注会话**再附 `sessionId`，删除附 `removed`，导入附 `report`。**登记**条目本身不属于任何**习惯日**，所以这些写接受一个可选的"视点日"（`date`，默认今天）：客户端把**它正在看的那一天**送上去，答案就是那一天的 slice，可以直接采纳。**素材清扫**是唯一例外——它回收孤儿字节，不改任何日也不改任何条目，答 `{ok, removed}`。

- **Status**: accepted
- **Considered Options**
  - 保留最小答复 + 客户端补读 —— 否决，这正是现状：**登记**编辑两个往返，且补读与写答案的先后决定屏幕上留哪个值。
  - 只答 `today` 的 slice，让看板自己 fold —— 否决：客户端算不出**格**（ADR-0002 禁止在客户端重算派生值），看板显示过去某天时会拿今天覆盖它。
  - 让客户端按答复里的 `entry` 自行维护列表 —— 否决：列表与 slice 又会分成两份真值。
- **Consequences**
  - 九个路由的答复变大（多一份已算好的 slice），但那是宿主本来就要算的东西；客户端只剩一条采纳路径。
  - 半更新安装（浏览器 bundle 热更新、宿主半身需 `dsh` 重启）里旧宿主答里没有 `day`，客户端回退为"再读一次"，与既有的 stale-host 姿态一致。
  - `label` 之类的显示字段因此能随 slice 走（统计热力网格的中文名不再由客户端自备）。
