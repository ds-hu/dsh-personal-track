# **待办**是第三种登记项，不是"字段更少的任务"

左栏原本是一张只读的卡：**最近专注**那一段会话。它能回答"上一次专注的是谁"，却接不住"我现在想做什么"——而那块地方是整个看板唯一空着的。于是左栏改成一张**待办**清单：写一条、勾一条，专注过的**任务**/**媒体**在下面派生出现。

实现只有两条路：给**任务**加一个"这是待办"的标记（复用它的存储、素材与专注），或者新开一张表。我们选了后者，把**待办**登记成与**媒体**、**任务**并列的第三种**登记**项。

分水岭只有一条：**完成**是谁的事实。**任务**的 `state` 由**任务进度**轴派生（`current ≥ total` 且落 `completedAt`），**待办**的 `done` 是它自己存下来的事实。若把待办做成任务，两者必有一伤——要么给它造一条它本来没有的进度轴（于是"勾选"变成一次进度写），要么在派生规则里为它开一个例外（于是 `done` 与 `state` 两个词在同一张表里各说各话）。拆开之后规则各自干净：勾掉一条待办动不了任何进度条，完成一个任务也勾不掉任何待办。

- **Status**: accepted
- **Considered Options**
  - 给**任务**加 `kind: 'todo'` 标记 —— 否决：`done` 与派生的 `state` 会在同一张表里互相矛盾，而且待办会渗进任务卡、**健身格**与任务统计（它们都按"任务"读那张表）。
  - 复用**媒体**那张日志形的表 —— 否决：日志形的状态机（在列/完成/弃）与"勾掉"不是一回事，硬套会让一个二值事实长出三个没用的状态。
  - 独立表 + 独立路由 —— 采纳。
- **Consequences**
  - **同权**：`OwnerKind` 与 `RegistryKind` 从二值变三值，素材、备注、**专注会话**与**专注模式**因此免费复用；专注模式的元信息行多一个分支，而不是多一套模式。
  - **不进统计**：待办不属于任何**习惯日**，也不参与任何**习惯**的完成率。要统计的工程量记在**任务**上。
  - **写入答复仍是那一种形状**（ADR 0004）：slice 多一个 `todos` 数组，`entry` 可能是待办。
  - **备份升到 v4**：文件多出 `todos`。旧文件（v1–v3）照常导入，缺这个数组就是没有待办；反过来旧版本读 v4 会被版本号拦住，而不是静默丢掉整张清单。
  - **左栏的下半栏是派生的，而且不含待办**：待办已经在上面那张清单里，再列一次就是同一行画两次；下半栏只收"没有进待办"的登记项（任务、媒体），并按**最近一次已闭合会话**排序——它回答"我刚才在做哪件"，总时长是数量、印在行上。
  - **名字推翻了 `CONTEXT.md` 的一条 Avoid**：当初为避免与 DSH 的**会话级 Todo** 撞词而避开"Todo / 待办"，实测两者不同屏、不同存储、不同界面，于是重新采用，边界写进了**待办 Item** 词条。若要再改名，代价落在表名、路由、六个 copy 键与备份数组名上，收益只是一个几乎不会同屏的重名——所以这一次不改。
  - 左栏标题是真 `<button>`：它开专注模式，就必须能由键盘到达。
